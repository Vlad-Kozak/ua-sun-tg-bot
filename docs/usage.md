# Як користуватись

Бот дозволяє кликати людей у групі за **тегами** — `@all`, `@devs`, `@qa` —
замість того, щоб пам'ятати нікнейми. Працює і для тих, у кого юзернейма немає
взагалі.

---

## Найкоротше

```
@all               покликати всіх
@devs              покликати тег
/tags              які взагалі є теги
/tag_create devs   створити тег
/tag_add devs      додати людину (реплаєм на її повідомлення)
/rollcall          зібрати учасників кнопкою (адміни)
```

---

## Як покликати людей

Просто напишіть тег **у будь-якому місці звичайного повідомлення**:

```
@devs гляньте, будь ласка, PR #42
```

Бот відповість реплаєм на ваше повідомлення зі списком клікабельних згадок:

> 🔔 @devs
> **Оля**, **Петро**, **Ігор**

Кожне ім'я — справжня згадка: людині приходить нотифікація, навіть якщо в неї
немає `@username`.

### Регістр не важливий

`@devs`, `@DEVS`, `@DeVs` — це один і той самий тег. Те саме стосується команд:
`/tag_info DEVS` працює.

### Достатньо частини назви

Не обов'язково писати назву повністю:

```
@dev гляньте PR
```

> 🔔 @devops @devs
> **Оля**, **Петро**, **Ігор**

Якщо частина назви підходить кільком тегам — бот покличе **всіх**, об'єднавши
аудиторію без повторів.

Як саме шукається тег, у порядку спадання пріоритету:

1. **точний збіг** — якщо існує тег рівно `dev`, то `@dev` покличе тільки його
   й нікого більше;
2. **збіг за початком назви** — `@dev` знайде `@devs`, `@devops`, `@developers`;
3. **збіг за будь-якою частиною** — і лише якщо за початком не знайшлося нічого:
   `@end` знайде `@backend` і `@frontend`.

Точний збіг стоїть першим навмисно: інакше тег `@dev` неможливо було б покликати
окремо, поки в чаті існує `@devs`.

Якщо частина назви підходить **більш ніж 5 тегам**, бот нікого не кличе, а
просить уточнити назву — щоб `@te` випадково не підняло пів групи.

### Звання з Telegram теж працюють як теги

Якщо в учасників є звання, видимі праворуч у списку групи («Mr Shishka Sun»,
«Igorita Moon»), їх можна кликати без жодного налаштування:

```
@sun збір о 20:00
```

> 🔔 @sun
> **Dimon**, **Andrusha**, **Yura**

Правила ті самі: регістр не важливий, достатньо частини слова (`@shish` знайде
«Mr Shishka Sun»), працює й кирилиця (`@лідер`).

Три особливості:

- **Нічого не треба створювати й наповнювати.** Склад обчислюється щоразу
  наново з тих звань, які люди мають у Telegram просто зараз: змінили звання —
  змінився й склад.
- **Власні теги бота мають пріоритет.** Якщо існує тег `@devs`, то `@devs`
  покличе саме його, навіть коли в когось у званні теж є «Devs».
- **Бот знає звання лише тих, кого вже бачив.** Звання приходить разом із
  повідомленням, тож мовчуни в такі згадки не потраплять — тут допоможе
  `/rollcall`.

### Кілька тегів одразу

```
@devs @qa завтра о 10:00 демо
```

Бот об'єднає аудиторію обох тегів і не покличе нікого двічі. За одне
повідомлення обробляється **не більше 3 згадок** — щоб одним рядком не підняти
всю групу.

### `@all`

`@all` кличе всіх учасників, кого бот знає в цьому чаті. Синоніми:

```
@all   @everyone   @всі   @усі   @все
```

Це віртуальний тег: його не треба створювати й нікого в нього додавати — він
працює одразу після додавання бота в групу.

З `@all` не отримають нотифікацію:
- ви самі (автор повідомлення);
- інші боти;
- ті, хто зробив `/mute_me`;
- ті, хто вже вийшов із чату.

За замовчуванням `@all` доступний **лише адмінам** і має паузу 10 хвилин між
викликами. Адміністратор групи може це змінити — див. [Налаштування](#налаштування-чату).

### Коли бот мовчить

Якщо ви написали `@devs`, а реакції немає, можливі причини:

- **такого тега не існує** — бот свідомо ігнорує невідомі `@слова`, бо інакше
  реагував би на кожен звичайний `@username`. Перевірте `/tags`;
- **не вистачає прав** або **діє пауза** — тоді бот відповідає тихою реплаєм
  (без звуку) з поясненням, скільки лишилось чекати;
- **частина назви підходить надто багатьом тегам** — бот попросить уточнити;
- **тег порожній** — бот скаже, що кликати нема кого.

## Робота з тегами

### Подивитися, що є

```
/tags
```
> **Теги цього чату**
> • `@devs` (4) — Розробники
> • `@qa` (2)
>
> Хто в тезі: `/tag_info назва`

Число — скільки учасників тега досі перебуває в цьому чаті.

```
/tag_info devs
```
> **@devs** — 4
> *Розробники*
> • Оля
> • Петро
> • Ігор
> • Влад Козак

У командах назву тега теж можна писати частково й у будь-якому регістрі:
`/tag_info devel` знайде `@developers`. Але якщо під написане підходить кілька
тегів, команда **не вгадує** — показує список і просить уточнити:

> Під «dev» підходить кілька тегів: `@devops`, `@devs`.
> Уточніть назву.

Це свідомо: помилитися тегом у `/tag_delete` дорожче, ніж дописати назву.

### Створити тег

```
/tag_create devs Розробники
```

Перше слово — назва, решта — необов'язковий опис (до 256 символів).

Правила для назви:

| Правило | Деталі |
|---|---|
| Довжина | від 2 до 32 символів |
| Символи | літери (зокрема кирилиця), цифри, `_`, `-` |
| Регістр | не має значення: `@Devs` і `@devs` — один тег |
| Зарезервовані | `all`, `everyone`, `все`, `всі`, `усі`, `here`, `channel`, `admin`, `admins` |
| Ліміт | до 100 тегів на чат |

Приклади робочих назв: `devs`, `qa_team`, `back-end`, `бекенд`, `team2`.

### Видалити тег

```
/tag_delete devs
```
Скорочено: `/tag_del`.

### Додати людину в тег

Три способи — оберіть зручніший:

**Реплаєм** (працює завжди, навіть якщо в людини немає юзернейма):
> відповідаєте на будь-яке повідомлення людини командою
```
/tag_add devs
```

**За юзернеймом:**
```
/tag_add devs @vasyl
```

**Кількох одразу:**
```
/tag_add devs @vasyl @olha @petro
```

> Якщо бот відповідає «Не знаю таких: @vasyl» — він ще жодного разу не бачив цю
> людину. Хай вона напише будь-що в чат, або додайте її реплаєм на її
> повідомлення.

### Прибрати людину з тега

```
/tag_remove devs @vasyl
```
Або реплаєм на її повідомлення. Скорочено: `/tag_rm`.

## Команди для себе

Ці команди не потребують прав адміна — кожен керує лише собою.

| Команда | Що робить |
|---|---|
| `/join devs` | вписатись у тег самому |
| `/leave devs` | вийти з тега |
| `/me` | у яких я тегах і чи кличе мене `@all` |
| `/mute_me` | більше не отримувати `@all` |
| `/unmute_me` | повернутись у `@all` |
| `/forget_me` | прибрати себе з усіх тегів чату і зі списку `@all` |

**`/mute_me` глушить тільки `@all`.** Іменні теги (`@devs`) вас усе одно
дістануть — це адресне звертання до конкретної ролі, а не масова розсилка.
Щоб не отримувати і їх, вийдіть із тега: `/leave devs`.

**`/forget_me`** — разова зачистка. Наступне ваше повідомлення в чаті поверне
вас до списку `@all`, бо бот знову вас побачить. Якщо потрібен постійний ефект —
використовуйте `/mute_me`.

## Налаштування чату

`/settings` без аргументів показує поточний стан і доступний усім.
**Змінювати налаштування можуть лише адміністратори групи.**

```
/settings
```
> **Поточні налаштування**
> • `@all` може кликати: лише адміни
> • теги може редагувати: лише адміни
> • пауза між викликами тега: 10 хв
> • таймзона: Europe/Kyiv
> • тихі години: 23:00–08:00

| Команда | Що змінює |
|---|---|
| `/settings all_policy admins` \| `members` | хто може кликати `@all` |
| `/settings tag_policy admins` \| `members` | хто може створювати й редагувати теги |
| `/settings cooldown 600` | пауза між викликами одного тега, секунд (`0` — вимкнути) |
| `/settings timezone Europe/Kyiv` | таймзона для тихих годин |
| `/settings quiet 23 8` | тихі години: згадки йдуть без звуку |
| `/settings quiet off` | вимкнути тихі години |

Кілька уточнень:

- **`tag_policy` не впливає на `/join` і `/leave`** — вписатись у тег самому
  можна завжди.
- **Пауза рахується окремо для кожного тега.** Виклик `@devs` не блокує `@qa`.
  Для `@all` — своя окрема пауза.
- **Тихі години не скасовують згадку**, а лише надсилають її з вимкненим звуком.
  Повідомлення все одно з'явиться в чаті.
- Проміжок тихих годин може перетинати північ (`23 8` — це з 23:00 до 08:00).

### Скільки людей бот уже знає

```
/stats
```
> **Що я знаю про цей чат**
> • учасників у базі: 47
> • з них `@all` дістане: 45
> • виключили себе з `@all`: 2
> • власних тегів бота: 3
> • знаю рідних тегів Telegram: 12
> • усього в чаті за даними Telegram: 60
> • **ще не знаю: 12** — вони жодного разу себе не проявили

Якщо «учасників у базі» помітно менше, ніж реально в групі, — це або нормальний
процес наповнення (бот запам'ятовує людей, коли вони пишуть), або увімкнений
privacy mode. Див. [architecture.md](architecture.md#звідки-береться-список-учасників).

Рядок «знаю рідних тегів Telegram» показує, у скількох учасників бот побачив
звання — саме їх можна кликати як `@sun` чи `@moon`. Якщо там `0`, то або в
чаті таких звань немає, або їхні власники ще нічого не писали.

## Сценарії

### Нова група: зібрати всіх за день

Додайте бота, зробіть адміном — `@all` уже працює. Але спочатку бот не знає
нікого, і найшвидший спосіб це виправити:

```
/rollcall
```

Бот запостить повідомлення з кнопкою **✋ Я тут** — **закріпіть його**. Один
клік, і людина в базі: писати нічого не треба, чат не засмічується, а новачки
натискатимуть кнопку й через місяці. У самому повідомленні видно прогрес
(«Вже знаю: 12 з 47»), і це помітно підганяє людей.

Далі база доповнюється сама трьома шляхами: повідомлення, **реакції** та
кнопка. Реакції працюють пасивно — людина й так ставить емодзі під постом, і
цього достатньо, щоб бот її запам'ятав (потрібне адмінство бота).

Скільки лишилося — покаже `/stats`.

### Теги під команди розробки

```
/tag_create backend Бекенд
/tag_create frontend Фронтенд
/tag_create qa Тестування
```

Далі можна не додавати нікого вручну — попросіть людей вписатись самим:

```
/settings tag_policy members
```
> Тепер кожен може: `/join backend`

### Дозволити всім кликати `@all`

Для невеликої дружньої групи:

```
/settings all_policy members
/settings cooldown 300
```

Для великої робочої групи так робити не варто — залиште `admins`.

### Черговий на тижні

```
/tag_create duty Черговий
/tag_add duty          ← реплаєм на повідомлення чергового
```
Наступного тижня:
```
/tag_remove duty       ← реплаєм на попереднього
/tag_add duty          ← реплаєм на нового
```

## Часті питання

**Чи працює це в каналах?**
Ні, тільки в групах і супергрупах.

**Чи працює у форумах (групах із темами)?**
Так. Бот відповідає в тій самій темі, де його покликали.

**Чому бот бачить не всіх учасників?**
Telegram не дає ботам списку учасників групи — його неможливо отримати. Бот
накопичує базу з тих, хто пише в чат. Це не помилка налаштування, а обмеження
платформи; детально — в [architecture.md](architecture.md).

**Я створив тег `@all` — чому не працює?**
Таку назву створити не можна, вона зарезервована. `@all` і так працює без
створення.

**Чи побачить бот моє листування?**
З вимкненим privacy mode бот отримує повідомлення групи, де він доданий. Він
зберігає лише `user_id`, ім'я та `@username` — **тексти повідомлень не
зберігаються ніде**. Що саме лежить у базі — див.
[схему БД](architecture.md#що-зберігається).

**Я вийшов із групи — мої дані лишились?**
Бот позначає вас неактивним і прибирає з тегів цього чату. Профіль (ім'я,
`@username`) лишається, бо ви можете бути в інших чатах із цим ботом.

**Чому бот пише кількома повідомленнями замість одного?**
Згадки нарізаються на батчі по 6. У повідомленні з десятками згадок клієнти
Telegram часом не показують нотифікацію всім — дрібні батчі це обходять.
